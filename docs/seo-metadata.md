# SEO-метаданные

Правила формирования метаданных страниц: где лежит источник правды, как добавить метаданные новому
маршруту и что нужно сделать вне репозитория.

## Источник правды

| Что                                                          | Где                         |
| ------------------------------------------------------------ | --------------------------- |
| Имя бренда, базовое описание, шаблон заголовка, локаль, язык | `src/seo/brand.ts`          |
| Заголовки и описания направлений                             | `src/seo/cores.ts`          |
| Сборка `Metadata` страницы                                   | `src/seo/build-metadata.ts` |
| Абсолютные адреса для `sitemap`/`robots`                     | `src/seo/urls.ts`           |

Импортируйте всё через публичный API модуля — `#/seo`, а не через отдельные файлы.

Имя бренда живёт в коде, а не в переменных окружения: метаданные не должны расходиться между
стендами из-за незаполненной переменной.

## `NEXT_PUBLIC_APP_NAME` — это не бренд

Вопреки названию, переменная задаёт **идентификатор стенда**:

- `src/constants/env.ts` сравнивает её с `PRODUCTION_APP_NAME` (`'starskills'`), вычисляя
  `isProductionApp`;
- от `isProductionApp` зависит `app/robots.ts`: на непродовых стендах весь сайт закрыт
  `Disallow: /`;
- `next.config.ts` передаёт её же как имя Sentry-проекта.

Никогда не подставляйте её в заголовки и описания — для этого есть `BRAND_NAME`.

**При переименовании стенда** правьте `PRODUCTION_APP_NAME` и переменную окружения production
одновременно. Рассинхрон тихий: код перестаёт считать прод продом, и весь сайт уходит под
`Disallow: /` без единой ошибки в логах.

## Метаданные нового маршрута

Статический маршрут:

```ts
import { buildPageMetadata } from '#/seo'

export const metadata = buildPageMetadata({
	title: 'Заголовок страницы',
	description: 'Одно-два предложения о содержимом страницы.',
	path: '/route',
})
```

Приватный или служебный маршрут добавляет `noIndex: true`.

Динамический маршрут экспортирует `generateMetadata` и **не читает `searchParams`** — иначе
фильтры протекут в канонический адрес:

```ts
export async function generateMetadata({ params }: PageProps): Promise<Metadata> {
	const { id } = await params
	const entity = await getEntityById(id)

	if (entity == null) {
		notFound()
	}

	return buildPageMetadata({ title: entity.title, description: '…', path: `/route/${id}` })
}
```

Правила:

- `title` задаётся **без** имени бренда — суффикс добавляет `title.template` корневого layout.
- `path` — путь маршрута; в абсолютный адрес его разворачивает `metadataBase`.
- `generateMetadata` обязана пережить недоступность источника данных: ловите исключение и
  возвращайте валидный fallback, иначе метаданные уронят страницу, которая сама умеет показать
  состояние ошибки.
- Данные, нужные и метаданным, и странице, читайте через функцию, обёрнутую в React `cache()`
  (см. `src/modules/skills/server/skills-repository.ts`) — иначе один запрос страницы даст два
  обращения к бэкенду.

## Новое направление

1. Добавьте значение в OpenAPI-контракт и в `SKILL_CORES` (`src/constants/skill-cores.ts`).
2. Добавьте заголовок и описание в `CORE_SEO_COPY` (`src/seo/cores.ts`). Тип
   `Record<SkillCore, CoreSeoCopy>` исчерпывающий, поэтому без этого шага не соберётся `tsc`.

В `app/sitemap.ts` править ничего не нужно: направления выводятся из `SKILL_CORES`.

Строки направлений намеренно статические, а не из БД: метаданные не должны зависеть от доступности
источника данных, а частый маршрут каталога — делать лишний запрос ради `<title>`.

## Индексация

- `app/robots.ts` закрывает **весь** непродовый стенд.
- Отдельные маршруты закрываются через `noIndex: true` в `buildPageMetadata`. Сейчас это
  `/profile` и страница 404.
- `app/sitemap.ts` перечисляет только публичные существующие адреса. Приватные маршруты туда
  не добавляются.

## Ограничения текущей реализации

- **OG-изображений нет.** Отдаются только текстовые `og:*`/`twitter:*`. Добавление
  `opengraph-image` — отдельная задача.
- **Дедупликацию нельзя проверить unit-тестом.** React `cache()` мемоизирует только внутри
  RSC-рендера; в Node-окружении Vitest он вызывает функцию повторно. Проверяется вручную на
  запущенном сервере (см. `docs/DEVELOPMENT_PROCESS.md` и test-plan соответствующего change).
- **Streaming metadata.** На динамических маршрутах Next.js по умолчанию досылает метатеги после
  первичной разметки. Боты, не исполняющие JS, получают их в `<head>`; поведение не менялось.
