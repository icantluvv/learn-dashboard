# Кэш изученных навыков профиля

Страница профиля не выполняет серверную предварительную загрузку и не использует
`HydrationBoundary`. `ProfileView` получает текущего пользователя через
`useGetAuthMe`, затем `CompletedSkillsContent` загружает изученные навыки через
`useGetCompletedSkillsByCore` из `@repo/api` с ключом
`[...getCompletedSkillsByCoreQueryKey(), user.id]`.
Запросы используют общие настройки QueryClient без локального `staleTime`.

После успешной отметки или снятия отметки кнопка инвалидирует префикс
`getCompletedSkillsByCoreQueryKey()`. Активный запрос обновляется сразу; неактивный
запрос обновляется при возвращении в профиль через SPA-навигацию. Полная
перезагрузка страницы не требуется.

Клиентское обновление использует `GET /api/me/completed-skills`. Endpoint
определяет пользователя из сессии, возвращает 401 гостям и запрещает HTTP-кэш
через `Cache-Control: no-store`. Query key содержит идентификатор пользователя,
но endpoint не принимает его от клиента.

`packages/api/base/client.ts` относит `/api/me/completed-skills` к локальным
маршрутам данных профиля: запрос не использует BFF-prefix. В mock mode
он возвращает сгенерированный mock-ответ; в обычном режиме выполняется реальный
запрос с сессионными cookies. Ответ 401 обрабатывается общим API-клиентом.

Контракт описан в `api/src/paths/api_me_completed_skills.yaml`. Методы, хуки и
Zod-схемы создаются через `npm --workspace @repo/api run generate`.

Состояния загрузки и данных выбирает клиентский `ProfileView`. При ошибке
его auth-query (любой неуспешный ответ или сетевая ошибка) компонент отображает
`ProfileError` без клиентского редиректа. При первом посещении без клиентского
кэша отображается `ProfileLoading` до завершения запроса пользователя.
