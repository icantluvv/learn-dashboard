# catalog-cores Specification

## Purpose

Вводит направление (core) как обязательную характеристику навыка: задаёт закрытый список допустимых
значений, делает направление частью API-контракта и адресации каталога и определяет поведение
системы при неизвестном направлении.

## Requirements

### Requirement: Направление навыка

Каждый навык SHALL иметь ровно одно направление из набора `frontend`, `backend`, `devops`, `design`.
Система SHALL возвращать направление навыка в ответе `GET /api/skills` для каждого элемента списка и
в ответе `GET /api/skills/{id}`.

#### Scenario: Направление в элементе списка

- **WHEN** клиент запрашивает `GET /api/skills` и получает непустой список
- **THEN** каждый элемент списка содержит поле `core` с одним из значений `frontend`, `backend`,
  `devops`, `design`

#### Scenario: Направление в детали навыка

- **WHEN** клиент запрашивает `GET /api/skills/{id}` для существующего навыка
- **THEN** ответ содержит поле `core` с направлением этого навыка

### Requirement: Существующие навыки относятся к фронтенду

Все навыки, заведённые до введения направления, SHALL иметь направление `frontend`.

#### Scenario: Навык, созданный до введения направления

- **WHEN** клиент запрашивает навык, существовавший до введения поля `core`
- **THEN** его направление равно `frontend`

### Requirement: Фильтрация списка навыков по направлению

Система SHALL принимать в `GET /api/skills` необязательный query-параметр `core` и при его наличии
SHALL возвращать только навыки с точно совпадающим направлением. При отсутствии параметра система
SHALL возвращать навыки всех направлений.

#### Scenario: Запрос с фильтром по направлению

- **WHEN** клиент запрашивает `GET /api/skills?core=frontend`
- **THEN** возвращаются только навыки с `core = "frontend"`

#### Scenario: Направление комбинируется с остальными фильтрами

- **WHEN** клиент запрашивает `GET /api/skills` с `core` и одновременно с `search`, `topic`,
  `difficulty` или диапазоном количества вопросов
- **THEN** возвращаются только навыки, удовлетворяющие всем переданным фильтрам одновременно

#### Scenario: Направление без совпадений

- **WHEN** передан `core`, которому не соответствует ни один навык
- **THEN** система возвращает пустой массив `[]` со статусом 200

#### Scenario: Запрос без фильтра по направлению

- **WHEN** клиент запрашивает `GET /api/skills` без параметра `core`
- **THEN** возвращаются навыки всех направлений

### Requirement: Недопустимое направление отклоняется

Система SHALL отклонять запрос `GET /api/skills` со статусом 400, если значение `core` не входит в
допустимый набор направлений.

#### Scenario: Неизвестное значение фильтра

- **WHEN** клиент запрашивает `GET /api/skills?core=mobile`
- **THEN** система возвращает статус 400 и не возвращает список навыков

### Requirement: Направления читаются из базы данных

Система SHALL хранить поддерживаемые направления в таблице `public.cores`. Каждое направление
SHALL иметь уникальный `type`, отображаемое название `name`, описание `description`, ключ иконки
`icon`, признак доступности `isAvailable` и порядок отображения. `GET /api/cores` SHALL возвращать
все направления в порядке отображения.

#### Scenario: Получение направлений

- **WHEN** клиент запрашивает `GET /api/cores`
- **THEN** система возвращает статус 200 и список направлений из `public.cores`
- **THEN** каждый элемент содержит `type`, `name`, `description`, `icon` и `isAvailable`

#### Scenario: Пустая таблица направлений

- **WHEN** в `public.cores` нет строк и клиент запрашивает `GET /api/cores`
- **THEN** система возвращает пустой массив `[]` со статусом 200

### Requirement: Навык связан с направлением

Значение `skills.core` SHALL ссылаться на существующее `cores.type`. Удаление направления, на
которое ссылаются навыки, SHALL быть запрещено базой данных.

#### Scenario: Навык с неизвестным направлением

- **WHEN** выполняется вставка или обновление навыка с `core`, отсутствующим в `public.cores`
- **THEN** база данных отклоняет операцию нарушением внешнего ключа
