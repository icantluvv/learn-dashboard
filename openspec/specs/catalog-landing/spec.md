# catalog-landing Specification

## Purpose

Определяет страницу `/catalog` как витрину направлений каталога: точку входа, из которой
пользователь выбирает направление и попадает в соответствующий раздел, включая направления, которые
ещё не наполнены навыками.

## Requirements

### Requirement: Витрина направлений

Система SHALL запросить направления из базы данных при открытии `/catalog` и отображать по одному
баннеру на каждый элемент ответа. Баннер SHALL показывать полученные `name`, `description` и
иконку, выбранную по ключу `icon`, и SHALL вести по клику на `/catalog/{type}`.

#### Scenario: Открытие витрины

- **WHEN** пользователь открывает `/catalog`
- **THEN** отображаются баннеры всех направлений, полученных из базы данных
- **THEN** каждый баннер ведёт по ссылке `/catalog/{type}` своего направления

#### Scenario: Данные баннера получены из направления

- **WHEN** база данных возвращает направление с заданными `name`, `description` и `icon`
- **THEN** баннер показывает это название и описание
- **THEN** баннер использует локальную иконку, соответствующую безопасному ключу `icon`

### Requirement: Состояния загрузки направлений

Система SHALL показывать отдельное состояние загрузки до ответа `GET /api/cores`, сообщение об
ошибке при неуспешном запросе и пустое состояние, если запрос вернул `[]`.

#### Scenario: Направления загружаются

- **WHEN** запрос `GET /api/cores` ещё не завершён
- **THEN** пользователь видит сообщение о загрузке направлений

#### Scenario: Направления не загрузились

- **WHEN** запрос `GET /api/cores` завершается ошибкой
- **THEN** пользователь видит сообщение о невозможности загрузить направления

#### Scenario: Направления отсутствуют

- **WHEN** запрос `GET /api/cores` возвращает пустой массив
- **THEN** пользователь видит сообщение об отсутствии направлений

#### Scenario: Переход во фронтенд-раздел

- **WHEN** пользователь нажимает баннер направления «Frontend»
- **THEN** он попадает на `/catalog/frontend`

### Requirement: Витрина не показывает список навыков

Система SHALL не отображать на `/catalog` ни сетку карточек навыков, ни панель фильтров.

#### Scenario: На витрине нет каталога

- **WHEN** пользователь открывает `/catalog`
- **THEN** сетка карточек навыков и панель фильтров не отображаются

### Requirement: Незаполненные направления помечены на витрине

Система SHALL визуально помечать на витрине баннеры направлений, раздел которых ещё в разработке,
так, чтобы пользователь до перехода понимал, что навыков там пока нет. Такие баннеры SHALL
оставаться кликабельными.

#### Scenario: Баннер направления в разработке

- **WHEN** пользователь открывает `/catalog` и смотрит на баннер направления `backend`
- **THEN** баннер содержит пометку о том, что раздел в разработке
- **THEN** баннер по-прежнему ведёт на `/catalog/backend`

### Requirement: Раздел направления в разработке

Система SHALL отображать на `/catalog/{core}` для направления, у которого раздел ещё не наполнен
(`backend`, `devops`, `design`), сообщение «Раздел в разработке» по центру области содержимого, без
сетки карточек и без панели фильтров.

#### Scenario: Открытие раздела в разработке

- **WHEN** пользователь открывает `/catalog/backend`
- **THEN** отображается сообщение «Раздел в разработке»
- **THEN** сетка карточек навыков и панель фильтров не отображаются

### Requirement: Неизвестное направление в адресе

Система SHALL показывать страницу «не найдено», если сегмент направления в адресе не входит в набор
поддерживаемых направлений.

#### Scenario: Адрес с неизвестным направлением

- **WHEN** пользователь открывает `/catalog/mobile`
- **THEN** пользователю показывается страница «не найдено»
