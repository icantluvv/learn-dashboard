## Context

`BackButton` уже реализован и покрыт тестом в
`app/(main)/catalog/[core]/[id]/_components/skill-detail/back-button.tsx` — client-компонент на
`'use client'`, вызывает `router.back()` из `next/navigation`, использует `Button` из `@repo/core`
и иконку `ArrowLeft` из `lucide-react`. Он сейчас route-local для `/catalog/{core}/{id}`. У
компонента появляется второй потребитель — `/catalog/{core}`. Компонент не содержит доменной
(каталожной) логики — это универсальная UI-обёртка над `router.back()`, пригодная для любого
маршрута приложения, поэтому по AGENTS.md он размещается в `src/components` ("переиспользуемые
составные UI-компоненты"), а не в route-local `_components` ближайшего общего сегмента. См.
proposal.md — Why/What Changes.

## Goals / Non-Goals

**Goals:**

- Переиспользовать существующий `BackButton` без изменения его публичного API и поведения.
- Разместить его в `src/components`, согласно правилам размещения компонентов из AGENTS.md
  (переиспользуемый UI-компонент без доменной логики).
- Показывать кнопку только в ветке страницы `/catalog/{core}`, где направление доступно.

**Non-Goals:**

- Изменение текста, иконки или поведения кнопки.
- Изменение плейсхолдера недоступного направления (`CorePlaceholder`).
- Вынесение в `packages/core` — компонент не является примитивом дизайн-системы, он комбинирует
  существующий `Button` с конкретным навигационным поведением (`router.back()`), что характерно
  для составных компонентов `src/components`, а не примитивов.

## Decisions

- **Новое размещение**: `src/components/back-button/{back-button.tsx, back-button.test.tsx,
index.ts}`. Альтернатива — ближайший общий route-сегмент
  `app/(main)/catalog/[core]/_components/back-button/` — была рассмотрена и отклонена: компонент
  не привязан к домену каталога и не содержит бизнес-логики, то есть по классификации AGENTS.md
  ("инфраструктурные providers без знания бизнес-сущностей — в `src/components`") относится к
  shared-слою, а не к route-local коду конкретного поддерева. Альтернатива — оставить компонент в
  `skill-detail` и импортировать его оттуда в `/catalog/{core}` — отклонена, так как
  `skill-detail/` задуман как route-local набор для страницы навыка (см.
  `_components/skill-detail/index.ts`), и такой импорт создал бы зависимость каталога от
  внутренностей другой страницы.
- **Без модуля**: не создаётся `src/modules/catalog`, так как логика кнопки не доменная и не
  требует общего состояния между модулями — достаточно shared UI-компонента.
- **Условие показа**: кнопка добавляется в `CatalogCorePage` только в ветке после проверки
  `coreData.isAvailable`, рядом с существующим `HydrationBoundary`, а не в раннем `return` для
  недоступного направления — тем самым поведение для `CorePlaceholder` не меняется без явного
  требования.
- **Тест**: переносимый `back-button.test.tsx` переезжает как есть (использует
  `nextRouterMock`/`resetNextNavigationMock` из `#/tests/mocks/next-navigation`); отдельный тест
  на странице `/catalog/{core}` проверяет наличие кнопки через существующий page-level test
  (создаётся/расширяется при реализации).

## Risks / Trade-offs

- [Два `app/`-page.tsx теперь импортируют компонент из `src/components`, а не из соседней `app/`
  директории] → Митигация: это ожидаемое направление зависимостей по таблице слоёв AGENTS.md
  (`app/` → shared `src/*`), импорт через алиас `#/components/back-button` не создаёт обратной
  зависимости.
- [Снэпшоты/screenshots `back-button` при его наличии в старой директории] → Проверено при
  переносе: явных `__screenshots__` для `back-button.test.tsx` не найдено, миграция ограничивается
  исходным и тестовым файлом.

## Test strategy

- **Unit**: не требуется — логика кнопки не содержит чистых функций, выделенных из UI.
- **Component** (`*.component.test.tsx` / `vitest-browser-react`): перенесённый
  `back-button.test.tsx` проверяет клик и вызов `router.back()`; существующий page/`catalog`-тест
  дополняется проверкой наличия кнопки "Назад" на `/catalog/{core}` при доступном направлении и её
  отсутствия в плейсхолдере недоступного направления.
- **Integration/E2E**: не требуется — поведение полностью покрывается component-тестом с
  замоканной навигацией; отдельный критический сквозной путь не затрагивается.
- **Manual**: визуальная проверка позиционирования кнопки над `SidebarFilters`/`Catalog` на
  mobile/desktop breakpoints (см. test-plan.md).
