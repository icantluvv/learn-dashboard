## Context

`BackButton` уже реализован и покрыт тестом в
`app/(main)/catalog/[core]/[id]/_components/skill-detail/back-button.tsx` — client-компонент на
`'use client'`, вызывает `router.back()` из `next/navigation`, использует `Button` из `@repo/core`
и иконку `ArrowLeft` из `lucide-react`. Он сейчас route-local для `/catalog/{core}/{id}`. По
AGENTS.md ("общий код начинайте в самой узкой области и поднимайте только после появления второго
потребителя") у компонента появляется второй потребитель — `/catalog/{core}` — поэтому его нужно
поднять в ближайшую общую директорию `app/(main)/catalog/[core]/_components/`, а не дублировать и
не поднимать выше уровня, на котором есть реальные потребители. См. proposal.md — Why/What
Changes.

## Goals / Non-Goals

**Goals:**

- Переиспользовать существующий `BackButton` без изменения его публичного API и поведения.
- Разместить его в директории, общей для обоих маршрутов-потребителей, согласно правилам
  размещения компонентов из AGENTS.md.
- Показывать кнопку только в ветке страницы `/catalog/{core}`, где направление доступно.

**Non-Goals:**

- Изменение текста, иконки или поведения кнопки.
- Изменение плейсхолдера недоступного направления (`CorePlaceholder`).
- Вынесение `BackButton` в `src/components` — у него пока только два потребителя внутри одного
  поддерева маршрутов, подъём выше необязателен.

## Decisions

- **Новое размещение**: `app/(main)/catalog/[core]/_components/back-button/{back-button.tsx,
back-button.test.tsx, index.ts}`. Это ближайший общий сегмент для `/catalog/[core]/page.tsx` и
  `/catalog/[core]/[id]/page.tsx`, что соответствует правилу "компонент → маршрут → модуль →
  shared". Альтернатива — оставить компонент в `skill-detail` и импортировать его оттуда в
  `/catalog/{core}` — отклонена, так как `skill-detail/` задуман как route-local набор для
  страницы навыка (см. `_components/skill-detail/index.ts`), и такой импорт создал бы
  зависимость каталога от внутренностей другой страницы.
- **Без промежуточного модуля**: не создаётся `src/modules/catalog`, так как логика кнопки не
  доменная и не требует общего состояния между модулями — достаточно shared route-level
  компонента.
- **Условие показа**: кнопка добавляется в `CatalogCorePage` только в ветке после проверки
  `coreData.isAvailable`, рядом с существующим `HydrationBoundary`, а не в раннем `return` для
  недоступного направления — тем самым поведение для `CorePlaceholder` не меняется без явного
  требования.
- **Тест**: переносимый `back-button.test.tsx` переезжает как есть (использует
  `nextRouterMock`/`resetNextNavigationMock` из `#/tests/mocks/next-navigation`); отдельный тест
  на странице `/catalog/{core}` проверяет наличие кнопки через существующий page-level test
  (создаётся/расширяется при реализации).

## Risks / Trade-offs

- [Два page.tsx теперь импортируют компонент из директории, которая не является ни одним из них] →
  Митигация: директория `_components` на уровне `[core]` уже используется как общий слой для
  `SidebarFilters`/`Catalog`/`CorePlaceholder`; это ожидаемое место для общих для поддерева
  компонентов, импорт остаётся внутри границ `app/`.
- [Снэпшоты/screenshots `back-button` при его наличии в старой директории] → Проверить при
  переносе: явных `__screenshots__` для `back-button.test.tsx` не найдено, миграция ограничивается
  исходным и тестовым файлом.

## Test strategy

- **Unit**: не требуется — логика кнопки не содержит чистых функций, выделенных из UI.
- **Component** (`*.component.test.tsx` / `vitest-browser-react`): перенесённый
  `back-button.test.tsx` проверяет клик и вызов `router.back()`; существующий page/`catalog`-тест
  дополняется проверкой наличия кнопки "Назад" на `/catalog/{core}` при доступном направлении и её
  отсутствия в плейсхолдере недоступного направления.
- **Integration/E2E**: не требуется — поведение полностью покрывается component-тестом с
  замоканной навигацией; отдельный критический сквозной путь не затрагивается.
- **Manual**: визуальная проверка позиционирования кнопки над `SidebarFilters`/`Catalog` на
  mobile/desktop breakpoints (см. test-plan.md).
