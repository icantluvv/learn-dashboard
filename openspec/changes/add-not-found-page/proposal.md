## Why

`app/not-found.tsx` рендерит пустой `<div>` без заголовка, текста и способа вернуться на сайт.
Пользователь, попавший на несуществующий URL, видит белый экран без объяснения и без выхода —
это тупиковый UX-сценарий, требующий ручной навигации через адресную строку или кнопку "назад"
браузера.

## What Changes

- Наполнить `app/not-found.tsx` контентом: заголовок о том, что страница не найдена, поясняющее
  описание и кнопка/ссылка возврата на главную страницу.
- Использовать существующие UI-паттерны страницы (`@heroui/react` `Button`, `next/link`,
  `page-wrapper v-stack` layout classes), уже применяемые в `back-button.tsx` и
  `global-error.tsx`, не вводя новую библиотеку компонентов.
- Сохранить `data-testid="error-boundary"` на корневом контейнере для совместимости с уже
  написанными тестами/соглашениями об error-состояниях (см. `error-boundary.tsx`).
- Добавить component test, подтверждающий наличие заголовка, описания и работающей ссылки на `/`.

## Capabilities

### New Capabilities

- `not-found-page`: страница 404 приложения — отображение заголовка, описания и ссылки/кнопки
  возврата на главную при переходе на несуществующий маршрут.

### Modified Capabilities

_(нет — существующих capability для страниц ошибок в `openspec/specs` не найдено)_

## Impact

- Affected code: `app/not-found.tsx` (единственный рендер-файл), новый `app/not-found.test.tsx`
  (или co-located `*.component.test.tsx` согласно конвенции тестов).
- Affected routes: глобальный Next.js 404 fallback (`app/not-found.tsx`), срабатывает для любого
  несуществующего route во всём App Router.
- No API, env, или dependency изменений; используется только уже установленный `@heroui/react` и
  `next/link`.
