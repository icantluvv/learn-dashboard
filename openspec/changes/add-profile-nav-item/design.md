## Context

Мотивация — в `proposal.md` («Why»). Технически важно:

- Единый источник ссылок навигации — `src/components/navigation/nav-links.ts`: `NAV_LINKS`
  потребляется и `MainNav` (десктопный `Sidebar`), и `BottomNav`. Отдельный `BOTTOM_NAV_MENU_LINK`
  описывает кнопку «Меню», которая рендерится `AccountDrawer`, а не как ссылка.
- Блок аккаунта в `Sidebar` собирается цепочкой `AuthStatusSlot` (server) → `AuthStatus` (client) →
  `GuestLinks` | `ProfileCard`. Кнопка выхода сейчас живёт в `ProfileCard` вместе с
  `useTransition`-состоянием ожидания.
- Мобильный `AccountDrawer` отдельно вызывает `useSignOut` для своей кнопки выхода.
- Страница `/profile` (`ProfileAuthenticated`) уже реализует выход собственным обработчиком
  (`authClient.signOut` + сброс кэша + `router.refresh()`), не через `useSignOut`.

## Goals / Non-Goals

**Goals:**

- Добавить «Профиль» в навигацию в одном месте — в `NAV_LINKS` — так, чтобы десктоп и мобилка
  получили пункт без дублирования логики активного маршрута.
- Оставить `Sidebar` и `AccountDrawer` только информационными относительно аккаунта.
- Сохранить `BottomNav` читаемым при четырёх элементах на узких экранах.

**Non-Goals:**

- Не переписывать поведение выхода на `/profile` (в частности, не переводить `ProfileAuthenticated`
  на `useSignOut` и не добавлять туда индикатор ожидания) — это отдельная задача.
- Не менять серверный prefetch профиля и гидратацию.
- Не превращать блок аккаунта в `Sidebar` в ссылку на `/profile`: пункт навигации уже даёт переход.

## Decisions

**Решение: пункт «Профиль» добавляется в `NAV_LINKS`, а не отдельным элементом в каждом компоненте.**
`MainNav` и `BottomNav` уже итерируют по `NAV_LINKS` и применяют `isActiveRoute`, поэтому одна
строка в списке даёт нужный пункт в обеих раскладках с корректным `aria-current`. Альтернатива —
отдельная константа и ручной рендер в каждом компоненте — создала бы два места правки и разошедшуюся
логику активного состояния.

**Решение: иконка — `UserRoundIcon` из `lucide-react`.** Она визуально отличается от `MenuIcon`
кнопки «Меню», которая остаётся рядом в `BottomNav`, и согласуется с текущим набором иконок
(`HouseIcon`, `LayoutGridIcon`).

**Решение: `BOTTOM_NAV_MENU_LINK` и `AccountDrawer` сохраняются.** Пользователь подтвердил вариант с
четырьмя элементами в `BottomNav`. Дровер остаётся носителем логотипа и переключателя темы на
мобильных, поэтому его удаление потребовало бы отдельного места для темы.

**Решение: `ProfileCard` упрощается до вывода `AccountSummary`, а не удаляется.** Убираются
`useSignOut`, `useTransition`, `Button` и `LogOutIcon`; компонент остаётся точкой расширения блока
аккаунта в `Sidebar` и сохраняет существующую структуру импортов `AuthStatus`. Альтернатива —
рендерить `AccountSummary` прямо в `AuthStatus` и удалить файл — экономит один модуль, но переносит
вёрстку sidebar-блока в компонент-переключатель состояний; при этом `ProfileCard` перестаёт быть
client-only обязательным, поэтому директиву `'use client'` в нём можно сохранить без вреда (он всё
равно рендерится внутри client-компонента `AuthStatus`).

**Решение: `useSignOut` остаётся в кодовой базе.** После правок его потребителем не остаётся ни один
компонент оболочки, но хук — часть блока `auth-status` и используется в тестах существующего
контракта. Чтобы `knip` не сообщил о неиспользуемом экспорте, `AccountDrawer` перестаёт его
импортировать, а сам хук либо остаётся востребованным, либо удаляется в том же изменении — решение
принимается по факту прогона `npm run knip` (см. задачи).

**Решение: узкий, «жидкий» BottomNav вместо скролла.** Элементы уже имеют `flex-1` и `min-w-16`; при
четырёх элементах на 360px это даёт ~80px на элемент, чего достаточно для иконки 28px и подписи
`text-xs`. Отдельная адаптация (сокращение подписей, скролл) не вводится — проверяется ручным
чеком.

## Risks / Trade-offs

- [Четыре элемента в `BottomNav` могут переноситься или обрезаться на очень узких экранах (≤320px)]
  → ручная проверка на 320px и 360px; при переполнении — уменьшение `min-w` элемента, без изменения
  состава навигации.
- [Пользователь, привыкший выходить из `Sidebar`/дровера, не найдёт выход] → пункт «Профиль» теперь
  виден в обеих раскладках и ведёт прямо на экран с кнопкой «Выйти».
- [Тесты и эталонные скриншоты `BottomNav` завязаны на три элемента и на кнопку выхода] → тесты
  `bottom-nav`, `sidebar`, `auth-status`, `profile-card`, `account-drawer`, `main-nav` и E2E
  `sidebar-nav` обновляются в этом же изменении, устаревшие снапшоты перегенерируются.
- [`knip` может начать сообщать о неиспользуемом `useSignOut`] → прогон `npm run knip` входит в
  верификацию; при срабатывании хук удаляется вместе с его использованием в тестах.

## Test strategy

- **Static**: `npm run tsc`, `npm run lint`, `npm run fmt:check`, `npm run knip` — типы, неиспользуемый
  код после удаления кнопок выхода.
- **Unit**: `is-active-route` уже покрыт; добавляется кейс `/profile` и пары `('/profile', '/')`.
- **Component**: `main-nav` (три ссылки, активное состояние `/profile`), `bottom-nav` (четыре
  элемента, «Меню» без `href`), `sidebar` (нет кнопки «Выйти»), `account-drawer` (нет кнопки
  «Выйти» у авторизованного), `auth-status`/`profile-card` (блок аккаунта без действия выхода),
  `profile-view` (кнопка «Выйти» на экране авторизованного пользователя).
- **Integration**: не требуется — новых слоёв данных и провайдеров нет.
- **E2E**: `src/tests/e2e/sidebar-nav.spec.ts` — переход на `/profile` из `Sidebar` с проверкой
  `aria-current`; проверка, что в серверной разметке оболочки нет кнопки выхода.
- **Performance**: не требуется.
- **Manual**: `BottomNav` на 320px и 360px; отсутствие выхода в `Sidebar` и `AccountDrawer`;
  успешный выход со страницы `/profile` на мобильной ширине.

## Migration Plan

Изменение только клиентское и не требует миграций данных. Деплой обычный; откат — revert коммита.
