## Purpose

Установка сервиса на домашний экран телефона и компьютера: валидный web app manifest с иконками,
запуск в standalone-режиме и подсказка об установке, работающая и в браузерах с программным API
установки, и в iOS Safari, где такого API нет.

## ADDED Requirements

### Requirement: Валидный манифест приложения

Приложение SHALL отдавать web app manifest с непустыми `name`, `short_name` и `description`,
`display: standalone`, `start_url` на главную страницу и цветами темы, соответствующими реальной
палитре приложения. Манифест SHALL быть связан со страницей, чтобы браузер находил его без
дополнительных действий пользователя.

#### Scenario: Манифест доступен и заполнен

- **WHEN** запрашивается адрес манифеста
- **THEN** ответ успешен, его тип — манифест, и он содержит непустые `name`, `short_name`,
  `description`, `display: standalone` и `start_url`

#### Scenario: Страница ссылается на манифест

- **WHEN** запрашивается HTML любого маршрута
- **THEN** разметка содержит ссылку на манифест приложения

### Requirement: Иконки приложения

Манифест SHALL объявлять иконки размеров 192x192 и 512x512, а также отдельную иконку с
`purpose: maskable` — без неё Android обрезает изображение под маску произвольной формы.
Приложение SHALL дополнительно объявлять `apple-touch-icon`, который iOS использует для ярлыка на
домашнем экране. Каждый объявленный файл иконки SHALL существовать и отдаваться по своему адресу.

#### Scenario: Все объявленные иконки существуют

- **WHEN** запрашивается каждый файл иконки, указанный в манифесте и в метаданных страницы
- **THEN** каждый запрос возвращает успешный ответ с изображением, а не 404

#### Scenario: Маскируемая иконка объявлена

- **WHEN** читается манифест
- **THEN** среди иконок есть запись с `purpose`, включающим `maskable`

### Requirement: Запуск в standalone-режиме

При запуске с домашнего экрана приложение SHALL открываться без браузерной адресной строки, на
всю доступную область экрана, включая зоны под системными вырезами.

#### Scenario: Приложение открывается без адресной строки

- **WHEN** пользователь запускает установленное приложение с домашнего экрана
- **THEN** интерфейс отображается в standalone-режиме, без адресной строки браузера

#### Scenario: Нижняя навигация не перекрывается системным индикатором

- **WHEN** установленное приложение открыто на устройстве с системным индикатором внизу экрана
- **THEN** подписи нижней навигации не перекрываются индикатором

### Requirement: Баннер установки

Приложение SHALL показывать баннер с предложением установить приложение и кнопкой закрытия.
Баннер SHALL NOT показываться, если приложение уже запущено как установленное, если пользователь
ранее закрыл баннер или если установка в текущем браузере невозможна и подсказка для него не
предусмотрена. Отказ пользователя SHALL переживать перезагрузку страницы.

#### Scenario: Баннер предлагает установку в браузере с поддержкой установки

- **WHEN** браузер сообщает приложению о возможности установки
- **THEN** появляется баннер с действием установки и кнопкой закрытия

#### Scenario: Закрытие баннера запоминается

- **WHEN** пользователь закрывает баннер и перезагружает страницу
- **THEN** баннер больше не появляется

#### Scenario: Баннер скрыт в установленном приложении

- **WHEN** приложение запущено с домашнего экрана в standalone-режиме
- **THEN** баннер не отображается

#### Scenario: Баннер исчезает после установки

- **WHEN** пользователь завершает установку из баннера
- **THEN** баннер скрывается и не появляется снова

### Requirement: Установка в браузере с программным API

Если браузер предоставляет программный запрос установки, кнопка баннера SHALL вызывать именно его,
а не показывать инструкцию. Если пользователь отклонил системный диалог, приложение SHALL
скрывать баннер и SHALL NOT открывать диалог повторно само.

#### Scenario: Кнопка вызывает системный диалог установки

- **WHEN** пользователь активирует кнопку установки в браузере с поддержкой программной установки
- **THEN** открывается системный диалог установки, а не текстовая инструкция

#### Scenario: Отклонённый диалог не открывается повторно

- **WHEN** пользователь отклоняет системный диалог установки
- **THEN** баннер скрывается и диалог не открывается снова без явного действия пользователя

### Requirement: Подсказка для браузеров без API установки

В браузерах, где программная установка недоступна (iOS Safari), баннер SHALL показывать инструкцию,
как добавить приложение на домашний экран вручную, вместо неработающей кнопки.

#### Scenario: iOS Safari получает инструкцию

- **WHEN** пользователь открывает приложение в iOS Safari, где событие установки не происходит
- **THEN** баннер показывает шаги «Поделиться → На экран „Домой"» вместо кнопки установки

#### Scenario: Инструкция не показывается там, где установка работает программно

- **WHEN** браузер поддерживает программную установку
- **THEN** баннер показывает кнопку установки и не показывает инструкцию для iOS
