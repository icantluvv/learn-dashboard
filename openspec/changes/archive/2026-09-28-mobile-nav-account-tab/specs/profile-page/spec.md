## Purpose

Страница `/profile` — единая точка входа в аккаунт из мобильной навигации: показывает состояние
авторизации (загрузка, ошибка, гость, авторизованный пользователь) и служит целью перехода для
входа и регистрации.

## ADDED Requirements

### Requirement: Страница профиля рендерится на сервере с prefetch данных пользователя

Страница `/profile` SHALL быть Server Component и SHALL выполнять на сервере запрос данных текущего
пользователя (`auth me`), передавая результат в клиентскую часть страницы через гидратацию кэша
запросов, чтобы избежать обязательного повторного запроса при первой отрисовке на клиенте.

#### Scenario: Открытие страницы профиля

- **WHEN** пользователь (гость или авторизованный) открывает `/profile`
- **THEN** сервер выполняет запрос данных текущего пользователя до отправки HTML и передаёт
  результат клиентской части страницы через гидратацию кэша

### Requirement: Клиентская часть страницы профиля выбирает экран по состоянию запроса

Клиентская часть страницы `/profile` SHALL выполнять запрос данных текущего пользователя через
сгенerated клиентский хук и SHALL отображать ровно один экран в зависимости от состояния запроса:
экран загрузки, экран ошибки, гостевой экран или экран авторизованного профиля. Каждый экран SHALL
быть отдельным компонентом от компонента-обёртки страницы.

#### Scenario: Запрос выполняется

- **WHEN** клиентский запрос данных пользователя находится в состоянии загрузки
- **THEN** отображается экран загрузки и не отображаются остальные экраны

#### Scenario: Запрос завершился ошибкой, не связанной с отсутствием сессии

- **WHEN** клиентский запрос данных пользователя завершается ошибкой, отличной от «нет сессии»
- **THEN** отображается экран ошибки и не отображаются остальные экраны

#### Scenario: Пользователь не авторизован

- **WHEN** клиентский запрос данных пользователя завершается ошибкой «нет сессии»
- **THEN** отображается гостевой экран и не отображаются остальные экраны

#### Scenario: Пользователь авторизован

- **WHEN** запрос данных пользователя успешно завершается и возвращает данные пользователя
- **THEN** отображается экран профиля авторизованного пользователя с этими данными и не отображаются
  остальные экраны

### Requirement: Гостевой экран профиля предлагает войти или зарегистрироваться

Гостевой экран страницы `/profile` SHALL содержать текст-приглашение авторизоваться и SHALL
содержать две кнопки: переход на `/sign-in` и переход на `/sign-up`.

#### Scenario: Гость открывает /profile

- **WHEN** неавторизованный пользователь видит гостевой экран `/profile`
- **THEN** на экране показан текст-приглашение войти в профиль, кнопка «Войти», ведущая на
  `/sign-in`, и кнопка «Регистрация», ведущая на `/sign-up`
