## Why

Домашняя страница показывала статичный список карточек навыков без возможности найти нужный
навык среди десятков записей. Пользователю нужен способ сузить список по теме, сложности,
количеству вопросов и названию, не покидая страницу и не теряя возможность поделиться ссылкой
на отфильтрованный результат.

## What Changes

- Каталог разбит на переиспользуемые компоненты (`Catalog`, `SkillCard`, состояния загрузки/ошибки/пустого
  результата) вместо одного инлайнового блока разметки.
- Контракт `GET /api/skills` расширен опциональными query-параметрами `search`, `topic`, `difficulty`,
  `minQuestionsCount`, `maxQuestionsCount`.
- Мок-обработчик каталога теперь реально фильтрует данные по этим параметрам вместо того, чтобы всегда
  возвращать полный список.
- Сайдбар фильтров получил поля поиска по названию, выбор темы, выбор сложности, диапазонный слайдер
  количества вопросов и кнопку сброса всех фильтров разом.
- Состояние фильтров хранится в query-строке URL (через `nuqs`), поэтому им можно поделиться ссылкой и они
  переживают обновление страницы.
- Первая загрузка каталога выполняется на сервере и передаётся на клиент через React Query hydration —
  без фильтров карточки видны сразу, без мигания скелетоном; при изменении любого фильтра клиент сам
  перезапрашивает список через тот же React Query hook.
- Каждая карточка теперь ссылается на `/catalog/{id}` (создана страница-заглушка маршрута).

## Capabilities

### New Capabilities

- `skills-catalog`: список карточек навыков на главной странице — загрузка, состояния ошибки/пустого
  результата/скелетона, ссылка на страницу навыка.
- `skills-catalog-filters`: поиск, фильтрация по теме/сложности/диапазону количества вопросов и сброс
  фильтров, с синхронизацией состояния в URL и авто-обновлением списка карточек.

### Modified Capabilities

_(нет — контракт `GET /api/skills` не имел собственной спецификации на момент этого изменения)_

## Impact

- **API-контракт**: `api/src/paths/api_skills.yaml` — добавлены query-параметры; перегенерирован клиент
  `@repo/api` (`packages/api/base/codegen/**`).
- **Mock-режим**: `packages/api/base/mock-client.ts`, `packages/api/base/mock-scenarios.ts` — фильтрация
  мок-данных по параметрам запроса.
- **Frontend**: `app/(home)/page.tsx`, `app/(home)/_components/catalog/**`,
  `app/(home)/_components/sidebar-filters/**`, `app/(home)/_hooks/use-skills-filters.ts`,
  `app/(home)/_constants/difficulty-options.ts`, `app/catalog/[id]/page.tsx`.
- **Тестовая инфраструктура**: `vitest.config.ts` — HeroUI, React Query и nuqs testing adapter добавлены
  в `optimizeDeps`, иначе первый прогон browser-тестов ломался ошибкой дублирования React.
