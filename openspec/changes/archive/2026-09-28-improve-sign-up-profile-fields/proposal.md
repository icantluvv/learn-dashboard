## Why

Форма регистрации сейчас предлагает значение пола «Другой» и принимает аватар только как внешний
URL. Требуется оставить выбор пола «Мужской»/«Женский» и позволить пользователю загрузить файл
аватара прямо в форме, чтобы приложение само сохраняло изображение в базе и стабильно отдавало его
для отображения профиля.

## What Changes

- Ограничить новые регистрации значениями пола `male` и `female` в интерфейсе и серверной
  валидации; прямой запрос со значением `other` должен отклоняться.
- Заменить текстовое поле URL аватара на dropzone с выбором файла, drag-and-drop, предпросмотром и
  возможностью удалить выбранное изображение до отправки.
- Принимать регистрацию с необязательным изображением через multipart-поток, валидировать тип и
  размер файла на клиенте для быстрого feedback и повторно на сервере как на доверенной границе.
- Хранить байты аватара и его служебные данные в PostgreSQL в отдельной записи, связанной с
  пользователем и удаляемой каскадно вместе с ним.
- Добавить same-origin endpoint чтения аватара. Профиль пользователя возвращает URL этого
  endpoint, чтобы существующие компоненты могли запросить и отрисовать изображение без передачи
  base64/blob внутри JSON профиля.
- Гарантировать согласованное завершение регистрации: пользователь не должен получить успешный
  результат с потерянным выбранным аватаром; при ошибке сохранения выполняется компенсирующая
  очистка созданного пользователя и сессии.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `auth-pages`: состав формы регистрации, допустимые варианты пола, dropzone и валидация файла
  аватара.
- `user-auth`: серверный контракт регистрации, хранение аватара в БД и HTTP-выдача изображения.

## Impact

- Маршрут `/sign-up`, компонент `SignUpForm`, схемы и server action регистрации.
- Новый route handler выдачи аватара и изменение ответа `GET /api/me` в части значения `image`.
- OpenAPI-описание `AuthMe.image`: тип остаётся URI, пример и описание уточняются для same-origin
  endpoint; отдельный generated client для бинарного изображения не создаётся.
- Новая Supabase/PostgreSQL-миграция с таблицей аватаров; ограничение пола для новых регистраций
  применяется в серверной валидации без изменения уже сохранённых профилей.
- Компоненты профиля и шапки продолжат использовать поле `image`, но получат same-origin URL.
- Новая runtime-зависимость не предполагается; dropzone реализуется на нативных file input и
  drag-and-drop событиях поверх существующих примитивов `@repo/core`.

## Quality impact

- Уровень риска: P0 — меняется критический сценарий регистрации, запись в БД и выдача
  пользовательского изображения.
- Затронутые маршруты: `/sign-up`, `/api/me`, новый endpoint аватара, `/` и `/profile` как
  потребители изображения.
- Затронутые компоненты: форма регистрации, новый route-local dropzone, существующие avatar/profile
  consumers.
- Затронутые API: серверная регистрация, `GET /api/me`, новый `GET` endpoint изображения.
- TDD-порядок: failing test → implementation → green → refactor.
- Обязательные уровни: Static, Unit, Component и E2E; route handler проверяется unit-тестом на
  уровне Request/Response.
- Ручные проверки: drag-and-drop настоящего изображения, предпросмотр и отображение сохранённого
  аватара после перезагрузки.
- Откат: вернуть прежнюю форму и action, удалить новый endpoint; миграцию откатывать отдельной
  безопасной миграцией после решения о сохранённых аватарах.
