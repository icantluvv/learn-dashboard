## Purpose

Предоставляет клиенту профиля актуальный список изученных навыков текущего пользователя через
авторизованный API и обновляет отображение после изменения отметок в каталоге.

## ADDED Requirements

### Requirement: API возвращает изученные навыки текущей сессии

`GET /api/me/completed-skills` SHALL определять пользователя из сессии и возвращать только его
группы с полями `core`, `coreName`, `skills`, где навык содержит `id` и `title`. Успешный ответ
SHALL иметь `Cache-Control: no-store`. Без сессии endpoint SHALL возвращать 401.

#### Scenario: Получение списка авторизованным пользователем

- **GIVEN** пользователь A авторизован и имеет изученные навыки
- **WHEN** клиент запрашивает endpoint
- **THEN** ответ 200 содержит только группы пользователя A и запрещает HTTP-кэширование

#### Scenario: Нет изученных навыков

- **WHEN** авторизованный пользователь без изученных навыков запрашивает endpoint
- **THEN** ответ 200 содержит пустой массив

#### Scenario: Нет сессии

- **WHEN** клиент без сессии запрашивает endpoint
- **THEN** endpoint возвращает 401 без списка навыков

### Requirement: Профиль отображает состояния списка и переходы к навыкам

Профиль SHALL загружать список только при наличии пользователя, показывать отдельную загрузку
списка, пустое состояние или группы. При ошибке SHALL показывать сообщение и повторный запрос,
сохраняя ранее полученные группы, если они есть. Каждый навык SHALL ссылаться на его страницу.

#### Scenario: Загрузка списка

- **WHEN** пользователь загружен, а первоначальный запрос списка ещё выполняется
- **THEN** карточка пользователя доступна и секция навыков показывает загрузку

#### Scenario: Пустой список

- **WHEN** запрос успешно возвращает пустой список
- **THEN** секция сообщает, что изученных навыков пока нет

#### Scenario: Переход к изученному навыку

- **WHEN** пользователь нажимает навык в группе направления
- **THEN** открывается `/catalog/<core>/<id>` для выбранного навыка

#### Scenario: Ошибка и повторный запрос

- **GIVEN** запрос списка завершился ошибкой
- **WHEN** пользователь просматривает секцию и нажимает «Попробовать ещё раз»
- **THEN** ранее полученные группы остаются видимыми и выполняется повторный запрос;
  кнопка недоступна на время выполнения запроса

### Requirement: Список обновляется после изменения отметки и изолирован по пользователям

После успешной отметки или снятия отметки изученности система SHALL обновлять активный список
или запрашивать актуальные данные при возвращении в профиль без полной перезагрузки. Кэш списка
SHALL быть разделён по пользователям и SHALL NOT показывать навыки другого аккаунта.

#### Scenario: Возвращение после изменения отметки

- **GIVEN** пользователь просмотрел профиль и перешёл к навыку
- **WHEN** он успешно меняет отметку и возвращается в профиль через SPA-навигацию
- **THEN** список отражает новую отметку без полной перезагрузки страницы

#### Scenario: Смена аккаунта

- **GIVEN** в кэше сохранён список пользователя A
- **WHEN** профиль открывает пользователь B
- **THEN** список пользователя A не отображается и загружается список пользователя B
