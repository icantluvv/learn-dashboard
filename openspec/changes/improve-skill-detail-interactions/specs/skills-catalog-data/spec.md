## MODIFIED Requirements

### Requirement: Деталь скилла читается из Supabase

Система SHALL возвращать по `GET /skills/{id}` один скилл из таблицы `skills` в Supabase, в форме, соответствующей generated-схеме `GetSkillById200` (`title`, `questions`), либо ответ 404, если скилл с таким `id` отсутствует. Для запроса с действующей сессией ответ SHALL дополняться признаком `completed` — отметкой этого пользователя об изучении скилла; для анонимного запроса признак SHALL отсутствовать. Так как ответ зависит от пользователя, он SHALL NOT кэшироваться.

#### Scenario: Существующий скилл

- **WHEN** клиент запрашивает `GET /skills/{id}` с `id`, существующим в таблице `skills`
- **THEN** система возвращает 200 с объектом `{ title, questions }`, соответствующим строке с этим `id`

#### Scenario: Отсутствующий скилл

- **WHEN** клиент запрашивает `GET /skills/{id}` с `id`, отсутствующим в таблице `skills`
- **THEN** система возвращает 404 без данных скилла

#### Scenario: Существующий скилл для авторизованного пользователя

- **WHEN** авторизованный пользователь запрашивает `GET /skills/{id}` с существующим `id`
- **THEN** система возвращает 200 с объектом `{ title, questions, completed }`, где `completed` — отметка этого пользователя об изучении скилла

#### Scenario: Ответ детали скилла не кэшируется

- **WHEN** выполняется запрос `GET /skills/{id}`
- **THEN** ответ содержит директиву, запрещающую кэширование
